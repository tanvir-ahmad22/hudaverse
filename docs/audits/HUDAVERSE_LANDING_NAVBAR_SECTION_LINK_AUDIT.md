# HudaVerse Landing Page Navbar & Section Link Audit

**Audit date:** 2026-11-09 (Asia/Dhaka)  
**Audit type:** Read-only source audit  
**Application files modified:** None. This report is the only file created.

## 1. Scope and method

Read the governing `AGENTS.md`, supporting `AGENTS-02.md`, and `STRUCTURE.md` before reviewing the current source. Followed the current rendered route/component imports rather than treating component files or the dated inventory as proof of use. Inspected shared layout, desktop and mobile Navbar, Navbar config/locales, Landing route and section components, Explore route/section components, Footer component/locales, and route files. Ran TypeScript and ESLint. No browser click test was performed.

The current app exposes `/`, `/explore`, and `/about` as content routes. This matches the user-specified public website scope. Other routes mentioned by Navbar/Footer may be planned or intended for separate applications, but no corresponding route exists in the current `apps/web/app` tree; their destination ownership therefore requires clarification where source does not prove intent.

## 6. Desktop navigation findings

- Desktop Navbar renders from shared `navItems`; each parent link points to its configured page and child links/panel CTA use configured destinations.
- Explore, Learn, Knowledge, and Library show dropdown panels; About is a direct link.
- Desktop action buttons point to `/login` and `/get-started`, neither of which exists in the current route tree.
- At source level, the primary pages `/`, `/explore`, and `/about` are linked correctly. Missing routes and the two Explore anchor mismatches are detailed above.
- Hover/focus behavior, click navigation, keyboard behavior, and actual responsive visibility were not browser-tested.

## 7. Mobile navigation findings

- Mobile drawer uses the same `getNavItems()` source as desktop; parent destinations, child destinations, and panel CTA destinations therefore match.
- Parents with children render as accordion groups. Child, parent, panel CTA, logo, Sign In, and Get Started links call `handleNavigation()`, which closes the drawer. A pathname-change effect also closes it after route navigation. This is source-confirmed behavior; it was not exercised in a browser.
- Thus mobile contains the same broken/missing targets identified for desktop; no separate route mapping discrepancy was found.
- Small-screen language selector and search affordance are not destinations in the inventory. Actual drawer operation, keyboard access, viewport-specific disappearance, and close behavior remain unverified visually.

## 9. Broken, missing, duplicate, and unverified links

### Verified source-level problems

1. `Explore → A Day with HudaVerse` links to `#a-day`, but the rendered section ID is `day`.
2. `Explore → Your Journey` links to `#journey`, but no matching target or ExploreJourney render exists. The current Explore page also stops at ExploreDay despite the locked `AGENTS.md` Explore sequence listing ExploreJourney.
3. Navbar destinations `/learn`, `/knowledge`, `/library`, `/login`, and `/get-started` have no matching route in the current app. Their child/CTA links consequently cannot resolve locally either.
4. Footer has multiple absent local routes (table above) and destinations outside the approved `/`, `/explore`, `/about` public set. Several platform links are redirected to query anchors in Explore, while others remain absent; link behavior is inconsistent by label.
5. Mobile and desktop share destination data, so the same invalid destinations occur in both.

### Checks without a confirmed issue

- No duplicate IDs were observed in the enumerated Landing section targets. FAQ child IDs and Features tabs are generated from unique keys; this was source-inspected, not DOM-scanned.
- The app route inventory contains `/`, `/explore`, and `/about`; internal destinations were checked against it. A missing local route does not rule out an external rewrite/deployment route, which was not available for this audit.
- The Landing Final CTA `/#faq-heading` target exists.
- No browser click, deep-link scroll, JavaScript-driven query selection, or deployed redirect was tested.

## 12. Final verdict

**Audit outcome: Fail for complete navigation/link integrity; Pass for the Landing section order and shared desktop/mobile destination configuration.** Several current Navbar routes are absent, one Explore anchor is mismatched, one Explore target is missing, and Footer destinations materially exceed the user-specified three-page public scope. TypeScript and ESLint pass. Browser-level clicking and deployed route rewrites were not verified. This audit made no application changes and does not recommend a specific destination for ambiguous/planned links.
